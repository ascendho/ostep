# lab-tutorial

## 核心结论
这份文档是操作系统课程实验的**C语言编程环境实操指南**，核心目标是帮新手掌握“写代码→编译→构建→调试→查资料”的完整流程。其核心逻辑是“工具+库+文档”三位一体：通过`gcc`（编译）、`gdb`（调试）、`make`（项目构建）三大工具实现代码落地，借助C标准库/第三方库复用代码，依靠`man`页/info页/谷歌解决疑问，最终让学习者能独立完成OS实验的C语言项目开发与调试。

## 一、核心原则：学好C编程的3个关键

想高效完成C语言项目（尤其是OS实验），需优先掌握以下3点，而非单纯死记语法：
1. **精通工具**：熟练使用编译（`gcc`）、调试（`gdb`）、项目构建（`make`）工具，这是提升开发效率的核心；
2. **熟悉库**：了解C标准库（`libc`）及常用第三方库（如数学库`libm`）的使用规则，避免重复造轮子；
3. **善用文档**：会通过`man`页、info页或谷歌查询函数用法、头文件包含、结构定义等信息，解决实操中的疑问。

## 二、基础：简单C程序结构与规范
### 2.1 最小示例（`hw.c`）
```c
#include <stdio.h>  // 引入输入输出库（printf的声明在此）
int main(int argc, char *argv[]) {  // 程序入口，argc=参数个数，argv=参数数组
    printf("hello, world\n");  // 输出字符串，\n表示换行
    return 0;  // 返回0表示程序正常结束，非0表示异常
}
```

### 2.2 关键细节
- **头文件（`#include`）**：告诉C预处理器（`cpp`）将指定文件内容插入当前代码，需包含库函数的“声明”（如`stdio.h`包含`printf`的声明）；
- **程序入口（`main`函数）**：C程序必须有且仅有一个`main`函数，是操作系统启动程序的入口；
- **返回值**：返回值会传递给shell，可通过shell变量（如`$?`）查看，用于判断程序执行结果。

## 三、编译与运行：`gcc`的核心用法
`gcc`是“编译器驱动”，自动协调预处理、编译、汇编、链接四步流程，无需手动执行每一步。

### 3.1 编译四步流程
1. **预处理（`cpp`）**：处理`#include`、`#define`等指令，生成预处理后的C代码；
2. **编译（`cc1`）**：将C代码转换为机器相关的汇编代码；
3. **汇编（`as`）**：将汇编代码转换为二进制目标文件（`.o`）；
4. **链接（`ld`）**：将目标文件与库文件（如`libc`）合并，生成可执行文件。

### 3.2 常用`gcc`参数（必记）
| 参数       | 作用                                  | 示例                                  |
|------------|---------------------------------------|---------------------------------------|
| 无参数     | 默认生成可执行文件`a.out`             | `gcc hw.c`                            |
| `-o 文件名` | 指定可执行文件名称                    | `gcc -o hw hw.c`（生成`hw`而非`a.out`）|
| `-Wall`    | 开启所有警告（必须启用，修复所有警告）| `gcc -Wall hw.c`                      |
| `-g`       | 添加调试信息（`gdb`调试必需）         | `gcc -g hw.c -o hw`                   |
| `-O`       | 开启代码优化（调试时禁用，避免逻辑打乱）| `gcc -O -Wall hw.c`                   |
| `-c`       | 仅编译生成目标文件（`.o`），不链接    | `gcc -c hw.c`（生成`hw.o`）           |
| `-lm`      | 链接数学库（含`sin`、`tan`等函数）    | `gcc -o calc calc.c -lm`              |
| `-I 路径`  | 指定头文件搜索路径（如当前目录`.`）   | `gcc -I. hw.c`（从当前目录找头文件）  |
| `-L 路径`  | 指定库文件搜索路径                    | `gcc -L./lib hw.c -lfoo`（从./lib找`libfoo`）|

### 3.3 运行可执行文件
- 命令：`./可执行文件名`（`./`表示当前目录，避免与系统命令重名）；
- 示例：`./hw`（运行`hw`可执行文件）；
- 参数传递：运行时可带参数，如`./hw arg1 arg2`，此时`argc=3`，`argv[0]="./hw"`，`argv[1]="arg1"`，`argv[2]="arg2"`，`argv[3]=NULL`。

## 四、库链接：复用已有的代码
库是预编译的代码集合，分为静态库和动态库，链接库是为了复用代码（如数学运算、系统调用封装）。

### 4.1 库的分类与区别
| 类型       | 后缀   | 核心特点                                  | 优势                                  | 劣势                                  |
|------------|--------|-------------------------------------------|---------------------------------------|---------------------------------------|
| 静态库     | `.a`   | 代码直接整合到可执行文件中                | 运行时不依赖外部库，移植性强          | 可执行文件体积大，库更新需重新编译    |
| 动态库     | `.so`  | 程序运行时才加载链接，多个程序共享库代码  | 可执行文件体积小，库更新无需重新编译    | 运行时依赖库文件，移植性弱            |

### 4.2 链接规则
- **C标准库（`libc`）**：默认自动链接，无需额外参数（如`printf`、`fork`均在`libc`中）；
- **第三方库（如数学库`libm`）**：需用`-lXXX`参数指定（`XXX`为库名，省略`lib`前缀）；
- 示例：使用`tan`（正切函数）时，需包含`math.h`并链接`libm`：
  ```c
  #include <math.h>
  int main() { printf("%f\n", tan(3.14)); return 0; }
  ```
  编译命令：`gcc -o tan_demo tan_demo.c -lm`。

## 五、大型项目：分开编译与`Makefile`自动化
当程序拆分为多个文件（如`hw.c`、`helper.c`）时，分开编译可节省时间（仅重新编译修改过的文件），`Makefile`则自动化构建流程。

### 5.1 分开编译步骤
1. 编译每个`.c`文件生成`.o`目标文件（`-c`参数）：
   ```bash
   gcc -Wall -O -c hw.c  # 生成hw.o
   gcc -Wall -O -c helper.c  # 生成helper.o
   ```
2. 链接所有`.o`文件生成可执行文件：
   ```bash
   gcc -o hw hw.o helper.o -lm  # 链接时指定库（如-lm）
   ```

### 5.2 `Makefile`核心规则

`Makefile`通过“规则”定义构建逻辑，默认文件名是`Makefile`或`makefile`，运行`make`即可自动执行。

#### 5.2.1 基础规则格式
```makefile
目标（target）: 依赖（prerequisite）
    命令（command）  # 必须以单个Tab开头，不能用空格
```
- 目标：通常是可执行文件、`.o`文件或动作（如`clean`）；
- 依赖：生成目标所需的文件或其他目标；
- 命令：生成目标的具体操作（如编译、链接）。

#### 5.2.2 简单`Makefile`示例
```makefile
# 注释：#开头的行是注释
hw: hw.o helper.o  # 目标hw依赖hw.o和helper.o
    gcc -o hw hw.o helper.o -lm  # 链接生成hw

hw.o: hw.c  # 目标hw.o依赖hw.c
    gcc -O -Wall -c hw.c  # 编译生成hw.o

helper.o: helper.c  # 目标helper.o依赖helper.c
    gcc -O -Wall -c helper.c  # 编译生成helper.o

clean:  # 动作目标，无依赖
    rm -f hw.o helper.o hw  # 删除目标文件和可执行文件
```

#### 5.2.3 简化`Makefile`（变量+通用规则）
大型项目可通过变量和通用规则简化写法，新增文件只需修改变量：
```makefile
# 变量定义
SRCS = hw.c helper.c  # 所有.c文件
TARG = hw  # 可执行文件名
CC = gcc  # 编译器
OPTS = -Wall -O  # 编译参数
LIBS = -lm  # 链接库参数
OBJS = $(SRCS:.c=.o)  # 自动将SRCS中的.c替换为.o（如hw.c→hw.o）

# 默认目标（运行make时优先执行）
all: $(TARG)

# 生成可执行文件
$(TARG): $(OBJS)
    $(CC) -o $(TARG) $(OBJS) $(LIBS)

# 通用规则：所有.o文件依赖对应的.c文件
%.o: %.c
    $(CC) $(OPTS) -c $< -o $@  # $<=依赖文件（.c），$@=目标文件（.o）

# 清理目标
clean:
    rm -f $(OBJS) $(TARG)
```

#### 5.2.4 `Makefile`关键操作
- 构建项目：`make`（自动执行默认目标`all`，生成可执行文件）；
- 清理文件：`make clean`（执行`clean`目标，删除`.o`文件和可执行文件）；
- 核心逻辑：`make`会检查“目标文件”与“依赖文件”的修改时间，仅重新生成“依赖更新过”的目标，节省编译时间。

## 六、调试：`gdb`排查程序错误
`gdb`是GNU调试器，用于定位程序中的bug（如段错误、逻辑错误），核心是“断点+单步执行+变量查看”。

### 6.1 调试准备
编译时必须添加`-g`参数（生成调试信息），禁用`-O`（优化会打乱代码逻辑）：
```bash
gcc -g -Wall hw.c -o hw  # 生成带调试信息的可执行文件
```

### 6.2 `gdb`基本操作（交互式）
| 命令          | 作用                                  | 示例                                  |
|---------------|---------------------------------------|---------------------------------------|
| `gdb 可执行文件` | 启动gdb调试会话                       | `gdb hw`                              |
| `run`（`r`）  | 运行程序，可带参数                    | `r arg1 arg2`                         |
| `break 位置`（`b`） | 设置断点（位置=函数名/行号）          | `b main`（在main函数设断点）、`b hw.c:10`（在hw.c第10行设断点） |
| `next`（`n`） | 单步执行（跳过函数调用）              | `n`                                   |
| `step`（`s`） | 单步执行（进入函数调用）              | `s`                                   |
| `print 变量`（`p`） | 查看变量值（支持指针、结构体）        | `p p`（查看指针p的值）、`p p->x`（查看结构体指针p的x字段） |
| `quit`（`q`） | 退出gdb会话                           | `q`                                   |

### 6.3 调试示例（段错误排查）
假设程序因空指针 dereference 报错（`buggy.c`）：
```c
#include <stdio.h>
struct Data { int x; };
int main() {
    struct Data *p = NULL;  // 空指针
    printf("%d\n", p->x);  //  dereference空指针，触发段错误
    return 0;
}
```
调试流程：
1. 编译：`gcc -g buggy.c -o buggy`；
2. 启动gdb：`gdb buggy`；
3. 运行：`r`，gdb提示段错误发生在`p->x`所在行；
4. 查看变量：`p p`，显示`p = (struct Data *) 0x0`（空指针）；
5. 定位bug：空指针无法 dereference，需给`p`分配有效内存。

## 七、文档查询：解决疑问的3种方式
实操中遇到“函数怎么用”“结构有哪些字段”等问题，优先通过以下方式查询：

### 7.1 `man`页（手册）
- 作用：查询函数用法、头文件包含、返回值、错误码等；
- 命令：`man [section] 关键词`（section=手册章节，可选）；
- 章节说明：
  - section 1：系统命令（如`kill`命令）；
  - section 2：系统调用（如`fork`、`open`系统调用）；
  - section 3：库函数（如`printf`、`tan`库函数）；
- 示例：
  - 查`open`系统调用：`man 2 open`；
  - 查`printf`库函数：`man 3 printf`；
- 关键信息：`SYNOPSIS`（头文件包含+函数原型）、`RETURN VALUES`（返回值说明）、`ERRORS`（错误码说明）。

### 7.2 info页
- 作用：比`man`页更详细，适合深入学习GNU工具（如`gcc`、`make`）的高级用法；
- 启动：`info gcc`（查看gcc的info文档）；
- 特点：支持跳转、搜索，内容更全面。

### 7.3 其他查询技巧
- 查找结构定义（如`struct timeval`）：
  1. 写一个仅包含头文件的程序（`test.c`）：`#include <sys/time.h>`；
  2. 预处理：`gcc -E test.c`，输出中包含`struct timeval`的完整定义；
- 谷歌：遇到`man`页/info页无法解决的问题，直接搜索关键词（如“struct timeval 字段”），效率最高。

## 八、推荐读物（进阶必备）
文档推荐的经典书籍，适合深入学习C编程与UNIX系统开发：
1. 《The C Programming Language》（Brian Kernighan & Dennis Ritchie）：C语言圣经，最权威的入门与参考书籍；
2. 《Advanced Programming in the UNIX Environment》（W. Richard Stevens & Steve Rago）：UNIX系统编程必看，覆盖系统调用、文件IO、进程管理等；
3. 《Managing Projects with make》（Andrew Oram & Steve Talbott）：详细讲解`Makefile`的用法，适合大型项目构建；
4. 《Debugging with GDB》（Richard M. Stallman等）：`gdb`调试的权威指南；
5. 《Expert C Programming》（Peter Van der Linden）：深入C语言底层细节与编译器特性，提升编程功底。

## 九、总结
1. 本教程的核心是“实操流程”，而非C语言语法，重点掌握`gcc`（编译）、`make`（构建）、`gdb`（调试）的核心用法；
2. 关键原则：编译加`-Wall`（修复警告）、调试加`-g`（禁用优化）、大型项目用`Makefile`（自动化构建）、遇疑问先查`man`页（高效解决问题）；
3. 最终目标：能独立完成操作系统实验的C语言项目开发，包括多文件编译、自动化构建、bug排查等。
