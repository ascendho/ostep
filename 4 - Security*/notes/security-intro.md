# security-intro

## 核心结论
操作系统（OS）安全是所有应用安全的基石——OS控制所有硬件资源且承载所有上层软件，其安全漏洞会导致全面系统妥协。核心目标是**保障机密性、完整性、可用性**，通过“最小权限”“完全中介”等设计原则，结合进程隔离、系统调用校验等机制，实现资源的“可控访问”，同时需在安全性、易用性、性能之间平衡，避免因过度安全导致用户弃用。

## 一、OS安全的核心重要性
OS安全之所以关键，源于其在系统架构中的核心地位，具体体现在三方面：
1. **上层依赖**：所有应用、中间件都运行在OS之上，OS不安全则上层软件“无安全可言”（如同“建在沙子上的房子”）；
2. **硬件控制权**：OS直接管理处理器、内存、外设等所有硬件，可读取/修改任意进程内存、文件、寄存器，权限最高；
3. **复杂性与多进程挑战**：现代OS代码量大、逻辑复杂，易存在安全漏洞；且需支持多进程并发，需隔离不可信进程（如未知脚本）与可信进程，防止恶意行为扩散。

## 二、安全核心目标与策略
### 2.1 三大核心安全目标
所有OS安全机制都围绕以下目标设计，适用于绝大多数场景：
- **机密性（Confidentiality）**：保护信息不被未授权者获取（如信用卡号、个人文件）；
- **完整性（Integrity）**：确保信息/系统组件不被未授权篡改，且需保证真实性（如订单数量不被恶意修改，文件来源可验证）；
- **可用性（Availability）**：保障授权用户可正常访问信息/服务（如避免恶意进程占用CPU导致其他进程无法运行）。

### 2.2 延伸目标：非否认性（Non-repudiation）
补充目标，确保行为发起者无法事后否认（如电子交易中，付款方不能否认已付款），需通过日志、加密等机制实现。

### 2.3 关键维度：可控共享
安全并非“完全隔离”，而是“按需共享”——需明确“谁能访问、访问方式、访问范围”（如协作用户可修改共享文件，其他用户仅可读取）。

### 2.4 目标落地：安全策略
安全目标需转化为具体可执行的“安全策略”（如“仅用户A和B可写入文件X”），OS提供通用机制，通过策略配置实现灵活的安全控制。

## 三、安全系统设计8大核心原则
这些原则由Jerome Saltzer和Michael Schroeder提出，是构建安全系统的基石，忽略则会显著提升漏洞风险：
1. **机制精简（Economy of Mechanism）**：系统设计应简洁小巧，减少漏洞数量，便于理解和审计；
2. **默认安全（Fail-safe Defaults）**：默认配置为“最安全”（如默认拒绝未授权访问，而非默认允许）；
3. **完全中介（Complete Mediation）**：每次资源访问都需校验权限，不可省略（如每次文件读取都检查访问权限，而非仅首次检查）；
4. **开放设计（Open Design）**：假设攻击者知晓系统所有设计细节，安全不应依赖“隐藏设计”（实际攻击中攻击者常通过逆向获取设计）；
5. **权限分离（Separation of Privilege）**：关键操作需多重凭证（如双因素认证，需密码+硬件令牌），避免单一凭证泄露导致妥协；
6. **最小权限（Least Privilege）**：进程/用户仅获得完成任务必需的最小权限（如普通应用无需访问系统核心文件）；
7. **最少共享机制（Least Common Mechanism）**：不同进程使用独立数据结构/机制（如每个进程有独立页表），减少共享带来的攻击面；
8. **可接受性（Acceptability）**：安全机制需易用，过度复杂的安全策略会被用户弃用（如频繁输入复杂密码导致用户手写记录）。

## 四、OS安全的基础机制
OS通过底层机制将安全原则落地，核心围绕“资源隔离与可控访问”：
1. **进程隔离**：通过虚拟内存、进程控制块（PCB）等，确保进程只能访问自身地址空间，无法随意读取/修改其他进程内存（依赖硬件支持，如CPU的用户态/内核态切换）；
2. **系统调用校验**：所有硬件访问、系统服务（如文件读写、进程创建）都需通过系统调用，OS在调用时校验“调用者身份+权限”，拒绝未授权操作；
3. **硬件辅助安全**：依赖硬件特性增强隔离（如CPU的特权级、内存保护单元MPU），部分场景下使用“安全飞地（Security Enclaves）”，隔离敏感数据（如加密密钥），即使OS被妥协也能保护；
4. **默认隔离与按需共享**：默认拒绝进程间资源访问，仅通过OS提供的合法接口（如IPC、共享文件）实现可控共享，避免非法数据泄露。

## 五、关键权衡与注意事项
1. **安全性vs易用性**：过度安全会降低用户体验（如每步操作都需授权），最终导致用户绕过安全机制，反而更危险；
2. **安全性vs性能**：完全中介、加密等机制会增加开销，需优化（如合理缓存权限校验结果，避免重复计算）；
3. ** weakest link原则**：攻击者会选择最易突破的环节（如OS再安全，用户用“password”作为密码仍会被破解），需优先加固薄弱点；
4. **虚拟ization≠安全**：进程虚拟化可防止“意外干扰”，但无法抵御“恶意攻击”，且共享资源（如文件系统）可能成为攻击通道。

## 六、总结
1. OS安全是上层应用安全的前提，其核心是“可控访问资源”，而非“完全隔离”；
2. 安全目标聚焦机密性、完整性、可用性，落地需转化为具体策略，依赖通用机制实现；
3. 8大设计原则是安全系统的“指南针”，但需平衡安全性与实际使用场景；
4. OS通过进程隔离、系统调用校验等机制落地安全，硬件辅助是重要补充。
