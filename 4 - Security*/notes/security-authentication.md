# security-authentication

## 核心结论
身份认证是操作系统安全的基础，核心目标是**可靠绑定“主体（用户/进程）身份”与“访问权限”**——通过“你知道的事、你拥有的物、你本身的特征”三类凭证，验证主体声称的身份，确保进程仅能以授权身份执行操作。OS通过“进程身份继承+登录认证流程”落地身份绑定，同时依赖密码加盐哈希、多因素认证等机制，平衡安全性与易用性，避免单一认证方式的缺陷。

## 一、核心问题（CRUX）

1. 如何将进程与正确的主体身份（用户/组/程序）安全绑定，防止恶意篡改？
2. 如何验证人类用户的身份，确保其声称的身份真实有效？
3. 如何处理非人类主体（如Web服务器、嵌入式设备进程）的身份认证？
4. 如何设计认证机制，在抵御猜测、泄露等攻击的同时，兼顾用户易用性？

## 二、身份与进程的绑定逻辑
OS的所有安全决策依赖“进程身份”，身份绑定遵循以下核心规则：
1. **默认继承**：子进程默认继承父进程的身份（如shell启动的应用，继承shell的用户身份）；
2. **初始身份分配**：用户登录时，OS通过认证流程验证用户身份，为其创建初始进程（如shell、窗口管理器）并绑定该身份；
3. **特权身份修改**：仅特权进程（如root）可修改进程身份（如`sudo`命令），普通进程无法自行变更身份，防止身份伪造。

### 关键概念
- **主体（Principal）**：安全决策的核心实体，包括用户、用户组、程序等；
- **代理（Agent）**：代表主体执行操作的实体（如进程是用户的代理）；
- **凭证（Credential）**：记录身份与权限的OS数据结构（如PCB中的用户ID、组ID）。

## 三、三大经典认证方式
所有认证机制均基于“验证主体独有的特征”，核心分为三类，各有优劣与适用场景：

### 3.1 基于“你知道的事”（Knowledge-Based）
最常用的认证方式，核心是“共享秘密”，以密码（Password）为代表。

#### 核心机制：密码的安全存储与验证
- **核心问题**：直接存储密码易泄露，需避免明文存储；
- **解决方案：加盐哈希（Salted Hash）**：
  1. 存储时：生成随机盐值（Salt）→ 拼接密码与盐值 → 用加密哈希算法（如SHA-3）计算哈希值 → 存储“盐值+哈希值”（不存储明文密码）；
  2. 验证时：用户输入密码 → 拼接密码与存储的盐值 → 计算哈希值 → 与存储的哈希值比对，一致则认证通过；
- **关键作用**：盐值避免“彩虹表攻击”（预计算哈希值字典），加密哈希确保无法从哈希值反推密码。

#### 密码安全的关键优化
- **密码复杂度**：要求长密码（≥12位）+ 多字符类型（大小写、数字、特殊字符），抵御暴力猜测；
- **防猜测机制**：多次输错后锁定账号或延迟验证（如输错3次后5分钟内无法登录），抵御字典攻击；
- **密码管理器**：用户无需记忆复杂密码，管理器生成并加密存储密码，降低“弱密码”风险。

#### 优缺点
- 优点：无需额外硬件，易用性高；
- 缺点：易被猜测、泄露（如写在纸上、钓鱼窃取），依赖用户良好习惯。

### 3.2 基于“你拥有的物”（Possession-Based）
通过主体独有的物理设备或物品验证身份，核心是“实体控制权”。

#### 常见形式
- **硬件令牌**：如USB密钥、动态口令器（每30秒生成新口令），需插入设备或输入显示的动态码；
- **移动设备验证**：如手机短信验证码、认证App（如Google Authenticator）生成的一次性码；
- **智能卡**：存储身份信息的芯片卡，需专用读卡器读取。

#### 核心保障：动态更新
- 设备生成的凭证（如动态码）定期更新，即使泄露，有效期极短，降低风险；
- 若设备丢失，需结合其他认证方式（如密码），避免单一设备被盗导致身份冒用。

#### 优缺点
- 优点：安全性高于密码，不易被远程窃取；
- 缺点：需额外硬件/设备，易丢失，丢失后可能导致无法登录。

### 3.3 基于“你本身的特征”（Biometric-Based）
利用人体生理或行为特征认证，核心是“生物唯一性”。

#### 常见形式
- **生理特征**：指纹、面部、虹膜、声纹等；
- **行为特征**：打字节奏、操作习惯等。

#### 核心挑战：模糊匹配与误差权衡
- 生物特征无法精确复制（如两次指纹扫描的图像不完全一致），需“模糊匹配”；
- 误差权衡：
  1. 假阴性（False Negative）：合法用户被拒绝（如指纹识别失败），影响易用性；
  2. 假阳性（False Positive）：非法用户被通过（如伪造指纹通过识别），威胁安全性；
  3. 交叉错误率（Crossover Error Rate）：假阳性与假阴性率相等的点，是衡量生物认证精度的核心指标。

#### 安全注意事项
- 需专用硬件（如指纹传感器、摄像头），普通设备可能不支持；
- 远程生物认证风险高（如攻击者伪造生物特征的比特流），仅适用于本地设备（如手机指纹解锁）；
- 生物特征无法修改（如指纹泄露后无法更换），需搭配其他认证方式降低风险。

#### 优缺点
- 优点：无需记忆/携带，便捷性高；
- 缺点：精度有限、设备依赖强、特征泄露后无法挽回。

## 四、认证强化：多因素认证（Multi-Factor Authentication）
单一认证方式存在缺陷，多因素认证要求同时提供两类及以上凭证，大幅提升安全性：
- **典型组合**：密码（你知道的）+ 手机验证码（你拥有的）、指纹（你本身的）+ 动态口令（你拥有的）；
- **核心价值**：即使一种凭证泄露（如密码被盗），攻击者因缺少另一类凭证，仍无法完成认证；
- **应用场景**：银行转账、系统管理员登录、云服务访问等高危操作。

## 五、特殊场景：非人类主体认证
针对Web服务器、嵌入式设备进程等“无人类操作”的主体，认证逻辑如下：
1. **创建专用身份**：为非人类主体创建专属用户（如`webserver`用户），绑定最小权限；
2. **身份分配方式**：
   - 特权用户手动启动（如管理员登录后启动Web服务器，进程继承`webserver`身份）；
   - 特权命令授权（如`sudo -u webserver apache2`，直接以目标身份启动进程）；
   - 进程身份切换（特权进程启动后，切换为非人类主体身份，遵循最小权限原则）；
3. **安全控制**：仅授权特权用户（如系统管理员）为非人类主体分配身份，防止滥用。

## 六、OS登录认证流程（以Linux为例）
以传统Unix/Linux系统为例，完整流程展示身份认证如何落地：
1. 特权登录进程（`login`）提示用户输入用户名；
2. 提示输入密码（输入时不回显，防止偷窥）；
3. 登录进程查询密码文件，获取该用户的盐值、加盐哈希密码、用户ID、组ID、默认shell等信息；
4. 拼接用户输入的密码与盐值，计算哈希值，与存储的哈希值比对；
5. 比对成功：`fork`新进程，设置其用户ID/组ID，切换至用户主目录，`exec`默认shell；
6. 比对失败：拒绝登录，且不提示“用户名错误”还是“密码错误”，避免攻击者枚举合法用户名。

## 七、关键安全原则与优化
1. **避免存储明文秘密**：密码、密钥等需以哈希（加盐）或加密形式存储，禁止明文存储；
2. **最小信息泄露**：认证失败时不透露具体原因，登录过程中不回显敏感凭证（如密码）；
3. **防暴力攻击**：限制认证尝试次数、增加尝试间隔，抵御字典攻击与暴力猜测；
4. **易用性平衡**：认证流程不宜过复杂（如频繁输入多类凭证），否则用户可能绕过安全机制。

## 八、总结
1. 身份认证的核心是“验证主体独有的特征”，三类经典方式各有优劣，需根据场景选择；
2. OS通过“进程身份继承+登录认证”，将主体身份与进程绑定，为后续权限控制奠定基础；
3. 单一认证方式风险高，多因素认证是提升安全性的关键，尤其适用于高危操作；
4. 非人类主体的认证需“专用身份+特权控制”，确保身份分配的安全性。
