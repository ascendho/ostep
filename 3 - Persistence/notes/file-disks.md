# file-disks

## 核心结论
硬盘驱动器（HDD）是基于**磁存储**的持久化存储设备，核心特性是“按扇区寻址+机械运动驱动I/O”：I/O性能由**寻道时间、旋转延迟、传输时间**三者决定，其中寻道和旋转延迟是主要瓶颈。优化核心是“减少机械运动开销”——优先顺序访问、通过调度算法优化请求顺序、利用轨道偏斜和缓存降低延迟。磁盘调度的目标是平衡“最短服务时间”与“避免饥饿”，现代硬盘多采用内部SPTF调度（结合寻道和旋转延迟），OS层面辅助请求合并与队列管理。

## 一、核心问题（CRUX）
1. 硬盘如何存储和访问数据？接口与寻址方式是什么？
2. 硬盘I/O时间由哪些部分构成，如何计算？
3. 如何通过磁盘调度优化I/O性能，避免饥饿问题？
4. 硬盘的物理结构和特性（如轨道偏斜、多区域）如何影响访问效率？

## 二、接口与寻址方式
### 2.1 核心接口
- 寻址单位：**扇区（Sector）**，默认512字节（现代也有4KB），是硬盘的最小I/O单位；
- 寻址空间：扇区从0到n-1连续编号，硬盘可视为“扇区数组”；
- 原子性保证：仅单个扇区的写操作是原子的（断电时不会出现“部分写入”），多扇区写入可能出现“撕裂写（torn write）”；
- 未成文约定：连续扇区访问比随机访问快，顺序访问是最高效的模式。

### 2.2 多扇区与缓存
- 支持多扇区读写（如4KB、100MB），但原子性仅针对单扇区；
- 硬盘缓存（ track buffer）：8-32MB内存，用于缓存整磁道数据，加速后续同磁道访问；
- 写策略：
  - 写穿（Write Through）：缓存写入后需同步到磁盘才确认完成，安全但慢；
  - 写回（Write Back）：缓存写入即确认，后台同步到磁盘，快但断电可能丢失数据。

## 三、物理结构与几何特性
### 3.1 核心组件
| 组件         | 功能描述                                                                 |
|--------------|--------------------------------------------------------------------------|
| 盘片（Platter） | 圆形磁性介质，双面存储（每面为一个“表面”），材质多为铝+磁性涂层             |
| 主轴（Spindle） | 带动盘片旋转，转速（RPM）决定旋转延迟，现代硬盘转速7200-15000 RPM         |
| 磁道（Track）  | 盘片表面的同心圆，每个表面含数千个磁道，相邻磁道间距极小                 |
| 扇区（Sector） | 磁道上的512字节存储单元，每个磁道含数百个扇区                           |
| 磁头（Head）   | 每面一个，负责读写磁信号，固定在磁臂上，通过磁臂移动定位到目标磁道       |
| 磁臂（Disk Arm）| 带动磁头沿径向移动，实现跨磁道寻道                                       |

### 3.2 关键特性
- 主轴转速：转速越高，旋转延迟越低（10000 RPM → 单旋转时间6ms；15000 RPM → 4ms）；
- 多区域磁盘（Multi-zoned）：外磁道周长更长，扇区数量比内磁道多，外区存储密度更高；
- 轨道偏斜（Track Skew）：跨磁道时，相邻磁道的扇区错开一定数量（如2个），避免磁头移动后目标扇区已旋转错过，减少旋转延迟。

## 四、I/O时间计算
### 4.1 核心公式
硬盘I/O总时间 = 寻道时间（T_seek） + 旋转延迟（T_rotation） + 传输时间（T_transfer）  
\[ T_{I/O} = T_{seek} + T_{rotation} + T_{transfer} \]

### 4.2 各组件详解
#### 1. 寻道时间（T_seek）
- 定义：磁臂移动到目标磁道的时间，含加速、匀速、减速、稳定四个阶段；
- 典型值：4ms（高性能硬盘）-9ms（容量型硬盘）；
- 平均寻道距离：约为总磁道数的1/3（通过积分计算得出）。

#### 2. 旋转延迟（T_rotation）
- 定义：目标扇区旋转到磁头下方的时间；
- 平均延迟：单旋转时间的1/2（随机请求下，平均需等待半圈）；
- 计算示例：10000 RPM → 单旋转时间=60秒/10000=6ms → 平均旋转延迟=3ms。

#### 3. 传输时间（T_transfer）
- 定义：数据在硬盘与内存间传输的时间；
- 计算公式：\[ T_{transfer} = \frac{传输数据量}{硬盘最大传输速率} \]
- 典型值：高性能硬盘125 MB/s，容量型105 MB/s，4KB数据传输仅需30微秒（可忽略）。

### 4.3 性能对比示例（随机vs顺序访问）
以Seagate Cheetah（15000 RPM，平均寻道4ms）和Barracuda（7200 RPM，平均寻道9ms）为例：
|  workload   | Cheetah（高性能） | Barracuda（容量型） | 关键结论                     |
|-------------|-------------------|---------------------|------------------------------|
| 随机4KB读   | T=4+2+0.03≈6ms    | T=9+4.17+0.03≈13.2ms | 随机访问性能差距达2倍以上     |
| 顺序100MB读 | T=4+2+800≈806ms   | T=9+4.17+952≈965ms  | 顺序访问接近最大传输速率，差距缩小 |

## 五、磁盘调度算法
核心目标：通过优化请求执行顺序，减少总I/O时间（重点降低寻道和旋转延迟）。

### 5.1 SSTF（Shortest Seek Time First，最短寻道时间优先）
#### 逻辑
- 选择当前磁头位置最近的磁道请求优先执行，贪心策略优化寻道时间。
#### 优点
- 比FIFO减少平均寻道时间，简单易实现。
#### 缺点
- 饥饿问题：持续有近磁道请求时，远磁道请求永远无法执行。

### 5.2 电梯算法（Elevator/SCAN/C-SCAN）
#### 核心改进
- 避免饥饿：按磁道顺序“扫掠”（如从外到内），仅服务当前扫掠方向上的请求，反向扫掠时服务另一侧请求。
#### 常见变体
- SCAN（双向扫掠）：磁臂在内外磁道间往返，服务路径如电梯升降；
- C-SCAN（循环扫掠）：仅单向扫掠（如外→内），到达一端后直接重置到另一端，避免中间磁道优先；
- F-SCAN：扫掠时冻结请求队列，新请求需等待下一轮，进一步保证公平性。

### 5.3 SPTF（Shortest Positioning Time First，最短定位时间优先）
#### 逻辑
- 不仅考虑寻道时间，还结合旋转延迟，选择“寻道+旋转”总时间最短的请求，更贴近SJF（最短作业优先）。
#### 优势
- 现代硬盘转速与寻道时间相当，考虑旋转延迟能进一步提升性能。
#### 实现场景
- 多在硬盘内部控制器实现（OS无法获取磁头旋转位置等细节），OS仅需批量下发请求。

### 5.4 其他调度优化
- 请求合并：将相邻扇区请求（如33和34）合并为单个多扇区请求，减少请求开销；
- 预期调度：非工作守恒策略，短暂等待新请求以合并或选择更优请求，提升整体效率。

## 六、关键特性与优化
### 6.1 轨道偏斜（Track Skew）
- 问题：跨磁道顺序访问时，磁头移动需要时间，目标扇区可能已旋转错过，导致额外旋转延迟；
- 解决方案：相邻磁道的扇区错开一定数量（如2个），确保磁头移动后，目标扇区刚好旋转到磁头下方。

### 6.2 多区域磁盘（Multi-zoned）
- 设计：将磁盘分为多个区域，外区磁道扇区数多于内区（外区周长更长）；
- 优势：提升外区存储密度和传输速率，充分利用物理空间。

### 6.3 硬盘缓存与写策略
- 缓存作用：缓存整磁道数据，加速同磁道后续访问；
- 写穿vs写回：写穿安全但慢，写回快但有数据丢失风险，需文件系统配合（如日志）保证一致性。

## 七、核心总结
1. 硬盘I/O性能瓶颈是**机械运动**（寻道+旋转延迟），传输时间可忽略，因此优先顺序访问是关键优化；
2. 调度算法演进：SSTF（贪心寻道）→ 电梯算法（公平性）→ SPTF（结合旋转延迟），现代硬盘以内部SPTF为主；
3. 物理特性优化：轨道偏斜解决跨磁道顺序访问延迟，多区域设计提升外区容量和速率；
4. 核心权衡：性能（SSTF/SPTF）与公平性（电梯算法）、速度（写回缓存）与安全（写穿缓存）。
