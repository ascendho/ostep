# file-ffs

## 核心结论
FFS（Fast File System）是为解决旧UNIX文件系统性能问题而生的“磁盘感知型”文件系统，核心创新是**“分组管理+局部性分配”**：通过将磁盘划分为块组（cylinder/block group），把相关文件/目录集中存储在同一组，减少寻道开销；同时通过大文件分散策略、小文件优化、参数化布局等机制，解决碎片化和传输低效问题。其核心教训是“把磁盘当磁盘对待”，充分考虑机械存储的寻道/旋转延迟，成为现代文件系统（如ext2/3）的设计基石。

## 一、核心问题（CRUX）
如何通过磁盘组织结构和分配策略，解决旧文件系统的低性能、高碎片化问题？如何让文件系统“感知磁盘特性”，优化数据布局以提升吞吐量？

## 二、旧UNIX文件系统的核心痛点
旧文件系统因设计简单，完全忽视磁盘的机械特性，导致性能极差（仅能发挥2%磁盘带宽），核心问题有三：
1. **碎片化严重**：用自由链表管理空闲块，文件分配时直接取“下一个空闲块”，导致逻辑连续的文件在磁盘上分散，寻道开销巨大；
2. **数据布局无序**：文件的inode与数据块、同目录文件的块可能分散在磁盘各处，频繁触发长寻道；
3. **块尺寸过小**：默认512字节块，虽减少内部碎片化，但每块需独立定位，传输效率低。

## 三、FFS的核心解决方案：块组（Cylinder/Block Group）
### 3.1 块组的定义与结构
FFS将磁盘划分为多个**连续的块组**（早期叫“柱面组”，现代因磁盘隐藏几何结构，改称“块组”），每个块组是磁盘地址空间的连续片段（如每8个块为一个组），本质是“小型独立文件系统”，包含完整的管理结构：
| 块组内结构       | 作用                                                                 |
|------------------|----------------------------------------------------------------------|
| 超级块副本（S）  | 存储文件系统全局信息（块数、inode数等），多组备份提升可靠性（避免单副本损坏） |
| inode位图（ib）  | 标记组内inode的分配状态（0=空闲，1=占用）                             |
| 数据位图（db）   | 标记组内数据块的分配状态                                             |
| inode表          | 存储组内所有文件/目录的inode                                          |
| 数据区           | 存储组内文件数据和目录数据                                           |

### 3.2 块组的核心价值
- 局部性保障：同一组内的inode、数据块物理位置接近，寻道时间短；
- 负载均衡：目录和文件分散在不同组，避免单组过载；
- 碎片化控制：组内分配减少跨组寻道，降低全局碎片化。

## 四、FFS的分配策略：保持局部性
FFS的分配 mantra 是“**相关数据放一起，无关数据分开放**”，通过简单 heuristics 实现，基于“命名空间局部性”（同目录文件常被同时访问）。

### 4.1 目录分配策略
- 目标：平衡各组目录数量，预留足够空闲inode（供后续文件分配）；
- 逻辑：选择“已分配目录少+空闲inode多”的块组，将目录的inode和数据块放入该组。

### 4.2 文件分配策略
1. 同组分配：文件的inode与数据块放在同一组，避免inode与数据块的长寻道；
2. 同目录聚集：同一目录下的所有文件，均分配到该目录所在的块组，保障同目录文件的局部性。

### 4.3 局部性的实证支撑（SEER traces）
- 40%的文件访问是“同文件重访”或“同目录文件访问”（路径差异≤1）；
- 25%的访问是“相邻目录文件”（路径差异=2，如`proj/src/foo.c`与`proj/obj/foo.o`）；
- 证明“同目录/相邻目录文件集中存储”的策略能覆盖大部分访问场景，大幅减少寻道。

## 五、大文件例外策略
### 5.1 问题背景
若大文件的所有块都放入同一组，会占满组内空闲空间，导致后续同目录的小文件无法在该组分配，破坏局部性。

### 5.2 解决方案：分块分散存储
- 前12个直接块（48KB）：与inode同组，保障小文件性能；
- 后续块：每个“间接块对应的块集”（如1个一级间接块=1024个数据块=4MB）分配到不同组，选择低利用率组；
- 核心逻辑：通过“大chunk分配”摊薄寻道开销（amortization）——只要chunk足够大，传输时间远大于寻道时间，性能损失可忽略。

### 5.3 chunk大小计算（以50%带宽为例）
- 假设：磁盘寻道+旋转延迟=10ms，传输速率=40MB/s；
- 需传输10ms以平衡寻道开销，所需chunk大小=40MB/s × 0.01s=409.6KB；
- 结论：4MB chunk（1024个4KB块）足以让寻道开销占比极低（≈2.5%），接近峰值带宽。

## 六、其他关键优化
### 6.1 小文件优化：子块（Sub-blocks）
- 问题：4KB块对小文件（如2KB）造成内部碎片化（浪费50%空间）；
- 方案：引入512字节子块，小文件先分配子块，增长到4KB后合并为完整块；
- 优化：libc库缓冲写操作，默认按4KB批量写入，避免频繁子块合并的I/O开销。

### 6.2 低级别布局优化：参数化布局
- 问题：旧磁盘 sequential read 时，相邻块可能因旋转过快错过磁头，需等待整圈旋转；
- 方案：FFS根据磁盘参数（旋转速率、磁头移动速度），错开相邻块的物理位置（如跳过1块），确保发出下一个块请求时，磁头刚好到达；
- 现代替代：磁盘内置“磁道缓存”（track buffer），读取整道数据缓存，文件系统无需再关注该细节。

## 七、可用性改进
FFS除性能优化外，还新增多个提升实用性的功能，推动其广泛 adoption：
1. **长文件名支持**：突破传统8字符文件名限制，支持更具表达性的名称；
2. **符号链接（软链接）**：解决硬链接的限制（不能跨文件系统、不能链接目录），可创建任意文件/目录的别名；
3. **原子rename()**：文件重命名为原子操作，避免系统崩溃导致的文件名不一致，支持原子文件更新（如编辑器临时文件替换）。

## 八、核心对比：旧文件系统 vs FFS
| 特性                | 旧UNIX文件系统                | FFS                          |
|---------------------|-------------------------------|------------------------------|
| 磁盘组织结构        | 无分组，全局自由链表          | 块组划分，每组独立管理        |
| 分配策略            | 取下一个空闲块，无序          | 相关数据同组，无关数据分组    |
| 碎片化控制          | 无，严重碎片化                | 组内分配+大文件分散，低碎片化  |
| 小文件支持          | 512字节块，传输低效           | 子块+4KB块，平衡空间与效率    |
| 可用性功能          | 短文件名、硬链接              | 长文件名、符号链接、原子rename |
| 磁盘特性利用        | 无，视为随机访问内存          | 感知寻道/旋转延迟，优化布局    |

## 九、总结
1. FFS的核心创新是“磁盘感知”：不再将磁盘视为抽象块数组，而是充分考虑机械存储的寻道/旋转延迟，通过块组和局部性分配提升性能；
2. 关键策略：块组划分（局部性）、相关数据同组（命名空间局部性）、大文件分散（负载均衡）、子块（小文件空间效率）；
3. 遗产：现代文件系统（ext2/3/4、XFS）均继承其核心思想，仅在数据结构（如B树代替线性目录）、容错（日志）等方面扩展；
4. 核心教训：文件系统性能优化的关键是“顺应存储介质特性”——机械磁盘优化寻道，SSD优化擦写均衡，本质都是“介质感知”。
